## Corrections issues du vrai lancement

Le premier démarrage ROM a révélé une erreur de sérialisation TOML native,
malgré le succès de `melonDS.exe --help`. La table `[DSi]` doit être explicite
avant `[DSi.SD]` lorsque melonDS ajoute ses réglages. Un test compilé avec le
parseur de la version amont reproduit le plantage puis vérifie le format corrigé.
Le vrai jeu a ensuite démarré et sauvegardé avec ce fichier.

La copie répétée du catalogue Randomizer et la reconstruction des graphes
ralentissaient le thread Qt. Les données validées sont maintenant immuables et
partagées ; les signatures des fichiers et leur lien à la partie restent contrôlés.
La mesure de 30 secondes après reprise reçoit 138 messages supplémentaires :
âge maximal du fichier d'état de l'interface 1,02 s et des données reçues 3,14 s.
C'est une vérification de fraîcheur, pas un benchmark comparatif des émulateurs.

Une session précédente avec des dumps faulthandler périodiques a subi une
exception native Python. L'origine exacte de cette exception n'est pas établie.
La reprise ci-dessus, sans cette instrumentation, s'est fermée normalement ;
cela ne prouve pas à lui seul une stabilité de longue durée.

Les boutons et raccourcis de vitesse PCE ne pilotent pas melonDS : ils sont
désactivés pour ce moteur. Les contrôles, graphismes et save states se règlent
dans ses menus natifs, conformément au [guide de migration](melonds-migration.md).

n’est pas présenté comme une confirmation mémoire de la Route 1.

une partie pourtant suivie. Le correctif conserve le suivi historique des profils

régressions reproduisaient le défaut avant correction ; **76 tests ciblés**

Ces résultats ne constituent ni un test d’endurance ni une nouvelle sauvegarde
en jeu : ce dernier cycle a été exécuté dans le paquet 01.

Preuve : `runtime/frozen02-real-game-report.json`, qui référence les captures du
monde et de la page Connexion. Aucun faux message d’équipe ni écriture RAM

## Dernières vérifications du 24 octobre 2026

La suite complète du commit `0db6e499d25f39fd19802f909e1f4ceaa9ab7430`
a terminé avec **2 846 tests réussis, 1 échec et 1 ignoré**, code de sortie 1,
en 43 118,39 secondes, dont plusieurs interruptions de session prolongées.
Le test ignoré exige la création d'un lien symbolique, indisponible avec les
privilèges Windows du processus. Ce résultat n'est pas un succès global.

L'échec concerne `test_game_mode_explains_lua_lock_and_unlocks_after_confirmed_stop`.
L'examen de sa fixture révèle un message incompatible avec le protocole annoncé
et une capacité d'identification manquante. Les scénarios pouvaient donc atteindre
l'état déconnecté par expiration du délai, sans accepter l'événement de fermeture.
La reproduction avec une assertion explicite sur `emulator_closing` échoue dans
trois scénarios. La correction de cette fixture et la nouvelle suite complète
restent à vérifier ; aucun délai ou contrôle produit n'est assoupli.

Le correctif `271b7e1` nettoie le contexte Connexion lorsqu'une partie restaurée
au démarrage est détachée sans avoir ouvert le Mode Jeu. Deux régressions
reproduisent le nom périmé avant correction, tandis que les deux contrôles de
détachement d'une autre partie passent. Après correction, **85 tests ciblés**
passent en 151,72 secondes, couvrant les flux de parties et de connexion. Le
changement porte sur trois lignes de code d'interface ; les données ne changent
pas. Le paquet 02 précède ce correctif : sa reconstruction reste à effectuer.

Preuves locales : `runtime/full-suite-PCE-full-validation-0db6e49.json`,
`runtime/detach-context-before-valid.log` et `runtime/detach-context-after.log`.
